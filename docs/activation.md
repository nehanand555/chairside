# Activate services in order

Use a separate staging project with test payments first. All server secrets below belong in Supabase → Edge Functions → Secrets. Do not paste secrets into GitHub issues, source files or chat.

1. **Supabase database/auth and Google login.** Create your project; choose its region with your NZ data-residency requirements in mind. Add GitHub environment variable `SUPABASE_PROJECT_REF`, and environment secrets `SUPABASE_ACCESS_TOKEN` and `SUPABASE_DB_PASSWORD`. Run **Deploy configured services → backend** on `main`. This applies migrations and deploys functions. Existing projects must run it again after merging the Google login change: the new migration removes the verified-phone requirement for verified Google identities; do not edit or rerun older migrations manually. Leave the Supabase Phone provider disabled while SMS is not configured. Google login does not send SMS or require Twilio. Enable TOTP enrollment/verification for business/admin access. Set up Google using [Google sign-in setup](google-sign-in.md), then set the Auth site URL to your web origin and allow the exact native callback. Hosted Auth provider settings are configured in the dashboard; `db push` does not apply them.
2. **First admin.** Sign in to the app with your own Google account, save your name, and set up an authenticator from the Business tab. In the Supabase SQL editor, insert *your actual Auth user UUID* into `private.admins`: `insert into private.admins(user_id) values ('YOUR-USER-UUID');`. Refresh/sign in again. Never grant admin from user metadata or expose this SQL through the app. Business owners apply from Business; they add services/hours before an admin approves them.
3. **Map services.** Enable Maps JavaScript API, Maps SDK for Android/iOS and Places API (New) in your Google Cloud project with billing. Use separate restricted client keys for each platform; restrict the server Places key to Places API. Set low API quotas and billing alerts. Add the three public client keys as GitHub environment variables `GOOGLE_MAPS_WEB_KEY`, `GOOGLE_MAPS_ANDROID_KEY`, `GOOGLE_MAPS_IOS_KEY`. Put `GOOGLE_PLACES_KEY` in Supabase secrets. Registered businesses remain searchable by name/suburb even when public map listings are disabled. Home studios do not need a Google listing.
4. **Function protection.** Set `ALLOWED_ORIGINS` to your exact web origins, comma separated (for local web include `http://localhost:3000`). Set `RATE_LIMIT_SALT` to a long random secret and `DISCOVERY_DAILY_LIMIT=250` initially. Limits reduce API spend; also configure Google's provider-side quotas. Origin checks are not user authentication. Native app requests have no browser origin; protected functions still verify Auth tokens and database permissions.
5. **Web hosting.** Create a Cloudflare Pages Direct Upload project. Add environment variable `CLOUDFLARE_PAGES_PROJECT`, secrets `CLOUDFLARE_ACCOUNT_ID` and a restricted `CLOUDFLARE_API_TOKEN`, and variable `SUPPORT_EMAIL`. Deploy with **Deploy configured services → web**. Set Supabase Auth site URL, `APP_URL` and `ALLOWED_ORIGINS` to its HTTPS URL. Configure your own domain when ready. GitHub Pages is not used as the production booking/payment host.
6. **Stripe test mode.** Activate a New Zealand Stripe platform account and Connect. Set `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET`, and `APP_URL` to the web URL. Register a platform webhook for `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `refund.created`, `refund.updated`, plus connected-account `account.updated` events, pointing to `/functions/v1/stripe-webhook`. If using separate Connect/event endpoints, configure both to the same function with its matching signing secret (see note below). Approved providers select Stripe setup in Business settings and complete onboarding. Refresh payment status afterwards. Checkout offers cards and eligible Apple Pay/Google Pay; wallet availability must be tested on supported devices. The platform currently charges no application fee and bears Stripe destination-charge processing/dispute costs. Confirm this business model before live payments.
7. **Afterpay.** Leave `ENABLE_AFTERPAY=false`. Enable it only after Stripe confirms platform/provider eligibility, appropriate service timing and required account capabilities. Test its cancellation/refund flow separately. Adding the setting does not obtain Afterpay approval.
8. **Optional booking texts and scheduled refunds.** Google customers can book without a phone; My visits is the source for confirmations and queue updates. Keep Twilio credentials unset to leave SMS off. To enable booking texts later for verified-phone customers, first configure Supabase Auth with a paid SMS provider, low sending limits and Twilio geographic/spending controls. Auth OTP messages are independent of the booking worker. Configure `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM`, and a long random `WORKER_SECRET`. In Supabase Vault add `chairside_functions_url` (the full notifications function URL) and `chairside_worker_secret` (same worker secret). Run `supabase/schedule.sql` in the chosen project's SQL editor. This invokes the worker every minute for queue refresh, reminders and refunds. It is required even if booking texts are off, because refunds need processing. Monitor failures; an accepted SMS is not proof of delivery. Queue texts are a convenience; the app remains the source for current estimates.
9. **Pilot, then release.** Use two real customer phones and a separate provider account. Test home-address privacy, bookings racing for the same slot, cancellation, queue delays, payment webhooks, refunds, SMS consent changes, permissions denied, reconnect and account deletion. Finish operator contact/privacy/terms, retention policy, support procedures, restore testing, store privacy forms and release signing before opening to paying customers. Use a separate `production` GitHub environment and Supabase project; repeat deployment/configuration there with live credentials only after the pilot passes.

The webhook accepts a primary `STRIPE_WEBHOOK_SECRET` and optional `STRIPE_CONNECT_WEBHOOK_SECRET` for a separately configured connected-account endpoint. Never share signing secrets between unrelated services.

No keys are supplied in this repository. The Supabase URL/publishable key and restricted map client keys are public application configuration; service-role, Stripe, Twilio, worker and deployment credentials must stay server-side.
